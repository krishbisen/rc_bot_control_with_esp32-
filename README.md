## 🎯 Project Overview

This project demonstrates how to build an autonomous RC bot with end-to-end Bluetooth connectivity and automatic reconnection capabilities. The implementation uses the **L298N Motor Driver Module** to control two DC motors via PWM signals generated by ESP32 or Arduino Nano microcontrollers.

### Key Objectives:
- ✅ Control DC motors with variable speed using PWM
- ✅ Establish stable Bluetooth communication
- ✅ Implement automatic connection recovery
- ✅ Provide both wired and wireless control interfaces
- ✅ Progressive learning path from basic to advanced implementations

## 📥 Installation & Setup

### Step 1: Hardware Assembly

#### Motor Driver Connections:

```
L298N Pin Configuration:
┌─────────────────────────────────────────┐
│ L298N Module                            │
├─────────────────────────────────────────┤
│ Pin  │ Function    │ Connection          │
├──────┼─────────────┼────────────────────┤
│ IN1  │ Motor A Dir │ ESP32 GPIO 26       │
│ IN2  │ Motor A Dir │ ESP32 GPIO 27       │
│ ENA  │ Motor A PWM │ ESP32 GPIO 14 (PWM) │
│      │             │                    │
│ IN3  │ Motor B Dir │ ESP32 GPIO 32       │
│ IN4  │ Motor B Dir │ ESP32 GPIO 33       │
│ ENB  │ Motor B PWM │ ESP32 GPIO 25 (PWM) │
│      │             │                    │
│ GND  │ Ground      │ ESP32 GND           │
│ +5V  │ Logic Power │ ESP32 3.3V (via reg)│
│ +12V │ Motor Power │ Battery Positive    │
│ GND  │ Motor GND   │ Battery Negative    │
└─────────────────────────────────────────┘
```

#### Motor Connections:
```
Motor A (Left):  OUT1 & OUT2 of L298N
Motor B (Right): OUT3 & OUT4 of L298N
```

### Step 2: Software Installation

1. **Install Arduino IDE** from [arduino.cc](https://www.arduino.cc)

2. **Add ESP32 Board (for Bluetooth modules)**:
   - File → Preferences
   - Paste URL in "Additional Boards Manager URLs"
   - Tools → Board Manager → Search "ESP32" → Install

3. **Clone Repository**:
   ```bash
   git clone https://github.com/krishbisen/rc_bot_control_with_esp32-.git
   cd rc_bot_control_with_esp32-
   ```

4. **Select Board & COM Port**:
   - Tools → Board → ESP32 Dev Module (or Arduino Nano)
   - Tools → Port → Select your COM port

5. **Upload Code**:
   - Open desired .ino file
   - Click Upload (→ icon)
   - Wait for "Done uploading" message

### 4️⃣ Advanced Bluetooth with Auto-Reconnection
**File**: `Autobluethooth_connection_withhost/Autobluethooth_connection_withhost.ino`

**Purpose**: Production-grade Bluetooth with connection recovery

**Advanced Features**:
- ✅ **State Flag Management**: Track connection state dynamically
- ✅ **Auto-Reconnection**: Automatically attempts reconnection
- ✅ **Safety Timeout**: Motors stop if no command received (1000ms)
- ✅ **Connection Callbacks**: Real-time connection status handling
- ✅ **Diagnostic State Reporting**: Clear feedback of connection state

**State Machine**:
```
┌─────────────────────────────────────────────┐
│ STARTUP: Waiting for Bluetooth Connection    │
│ isConnected = false                         │
│ autoReconnectFlag = false                   │
└────────────┬────────────────────────────────┘
             │
    Device connects (callback event)
             ↓
┌─────────────────────────────────────────────┐
│ CONNECTED: Accepting Commands                │
│ isConnected = true                          │
│ autoReconnectFlag = false                   │
│ Motors respond to BT commands               │
└────────────┬────────────────────────────────┘
             │
  Connection dropped (callback event)
             ↓
┌─────────────────────────────────────────────┐
│ DISCONNECTED: Auto-Reconnecting              │
│ isConnected = false                         │
│ autoReconnectFlag = true                    │
│ Motors immediately stopped (safety)         │
│ Waiting for re-entry into range             │
└────────────┬────────────────────────────────┘
             │
    Device reconnects
             ↓
    Back to CONNECTED state
```

**Key Implementation Details**:

```cpp
// Connection Callback Function
void btCallback(esp_spp_cb_event_t event, esp_spp_cb_param_t *param) {
  if (event == ESP_SPP_SRV_OPEN_EVT) {
    // Connection established
    isConnected = true;
    autoReconnectFlag = false;  // RESET FLAG
    lastPacketTime = millis();
  } 
  else if (event == ESP_SPP_CLOSE_EVT) {
    // Connection lost
    isConnected = false;
    autoReconnectFlag = true;   // SET FLAG
    stopCar();                  // Immediate safety stop
  }
}

// Main loop logic
if (isConnected && !autoReconnectFlag) {
  // Connected state: process commands
} else if (autoReconnectFlag) {
  // Disconnected state: keep motors stopped
}
```

**Safety Features**:
- Motors stop immediately on connection drop
- 1-second timeout on command receipt
- Automatic re-pairing without manual intervention
- Clear diagnostic output for debugging

**Use Case**: Autonomous delivery bots, production RC vehicles, safety-critical applications

## 📡 Command Protocol

### Bluetooth Communication Format

**Protocol Type**: UART Serial over Bluetooth Classic  
**Baud Rate**: 115200 (for ESP32)  
**Data Format**: Single ASCII character commands

**Command Categories**:

#### Movement Commands (Immediate Effect)
| Command | Motor A | Motor B | Direction | Use |
|---------|---------|---------|-----------|-----|
| F | Forward | Forward | ↑ Forward | Move robot ahead |
| B | Reverse | Reverse | ↓ Backward | Move robot back |
| L | Reverse | Forward | ← Left Turn | Rotate left (tank) |
| R | Forward | Reverse | → Right Turn | Rotate right (tank) |
| S | Stop | Stop | ⊘ Stop | Halt movement |

#### Speed Commands
| Command | PWM Value | Speed Level |
|---------|-----------|-------------|
| 0 | 0 | Stop |
| 1 | 100 | 39% |
| 2 | 120 | 47% |
| 3 | 140 | 55% |
| 4 | 160 | 63% |
| 5 | 180 | 71% |
| 6 | 200 | 78% |
| 7 | 220 | 86% |
| 8 | 240 | 94% |
| 9/q | 255 | 100% (Max) |

## 🎮 Usage Guide

### Basic Operation

#### 1. Initial Setup
```bash
# Step 1: Assembly
- Mount motors on chassis
- Connect L298N module to motors
- Wire L298N to ESP32 per pinout
- Install battery pack

# Step 3: Testing
- Disconnect USB
- Apply battery power (8-12V to L298N)

- Should see initialization messages
```

#### 2. Bluetooth Control
```bash
# Step 1: Enable Bluetooth on Phone
- Settings → Bluetooth → ON

# Step 2: Pair Device
- Scan for "ESP32_BT_Car"
- Tap to pair (no PIN)

# Step 3: Install RC App
- Download "Bluetooth RC Controller" (Android/iOS)
- Or use "Serial Bluetooth Terminal"

# Step 4: Connect & Drive
- Open app
- Select "ESP32_BT_Car"
- Use on-screen controls or arrow keys
```

#### 3. Serial Monitor Debugging
```
Expected Output:
─────────────────────────────────────────────────────
System Ready. Waiting for Bluetooth connection...
===========================================
[STATE FLAG] autoReconnectFlag = FALSE
[STATUS] Device connected! Drive mode ACTIVE.
===========================================

Received: F (Forward command)
Received: 5 (Speed change)
Received: S (Stop command)

===========================================
[STATE FLAG] autoReconnectFlag = TRUE
[STATUS] Connection Lost! Motors killed.
[STATUS] Advertising... Waiting for device to re-enter range.
===========================================
```

### Advanced Features (Auto-Reconnection Module)

#### Testing Connection Recovery:

1. **Start** bot and connect via Bluetooth
2. **Verify** movement works (send 'F' command)
3. **Move Away** device out of range
4. **Observe** Serial Monitor:
   - Should show "Connection Lost"
   - Motors should stop immediately
   - State flag changes to TRUE
5. **Move Back** into range
6. **Observe** automatic reconnection
7. **Send Command** - bot resumes operation

#### Timeout Behavior:

```
Scenario: No command received for 1+ seconds while connected

Timeline:
T+0.0s  → Last valid command received
T+1.0s  → Timeout threshold exceeded
T+1.01s → Motors automatically stopped
T+1.02s → Serial Monitor shows timeout event
T+1.5s  → Ready for next command
```

## 🐛 Troubleshooting

### Problem: Motors Not Spinning

**Solution Checklist**:
```
☐ Battery connected and charged (check voltage: 7.4V+)
☐ Motor leads connected to L298N outputs (OUT1-4)
☐ ESP32 GPIO connected to L298N inputs (IN1-4, ENA-ENB)
☐ L298N power (+12V, GND) connected to battery
☐ No loose wires or burnt components
☐ Try manual movement test (run single motor code)
```

**Diagnostic Code**:
```cpp
void setup() {
  Serial.begin(115200);
  pinMode(ENA, OUTPUT);
  pinMode(IN1, OUTPUT);
  pinMode(IN2, OUTPUT);
}

void loop() {
  // Test Motor A forward
  digitalWrite(IN1, HIGH);
  digitalWrite(IN2, LOW);
  analogWrite(ENA, 200);
  delay(3000);
  
  // Check Serial output
  Serial.println("Motor A should spin forward");
}
```

### Problem: Connection Drops Frequently

**Solutions**:
```
1. Distance: Move closer to ESP32 (Bluetooth range ~10m max)
2. Interference: Avoid WiFi/microwave/2.4GHz devices nearby
3. Battery: Low battery voltage causes connection instability
   - Check battery: should be 7.4V+ (not <6.5V)
4. Antenna: Ensure antenna is properly connected
5. Firmware: Update Arduino ESP32 board package
```

**Stability Test**:
```
Run this code with Serial Monitor:
- Connect via Bluetooth
- Send 'F' every 500ms for 2 minutes
- Check for disconnections
- If stable: no additional issues
- If unstable: check battery voltage and distance
```

---

### Problem: Motors Acting Unexpectedly (Wrong Direction)

**Solution**:
```
Motor A spinning wrong direction?
→ Swap IN1 and IN2 connections on L298N

Motor B spinning wrong direction?
→ Swap IN3 and IN4 connections on L298N

Both motors reversed?
→ Swap motor leads on L298N outputs
```

**Direction Verification Code**:
```cpp
void loop() {
  // Test Motor A clockwise
  digitalWrite(IN1, HIGH);
  digitalWrite(IN2, LOW);
  analogWrite(ENA, 200);
  Serial.println("Motor A: CW");
  delay(3000);
  
  // Test Motor A counter-clockwise
  digitalWrite(IN1, LOW);
  digitalWrite(IN2, HIGH);
  analogWrite(ENA, 200);
  Serial.println("Motor A: CCW");
  delay(3000);
}
```

## 📖 Best Practices

### Code Modifications

**Safe Speed Range**:
```cpp
// Recommended PWM values for smooth operation
0    → Motors off (safe to run indefinitely)
50   → Low speed (for testing/debugging)
100-180 → Operational speed (efficient, stable)
200-240 → High speed (good for racing)
255  → Maximum (max torque, max current draw)
```

**Adding New Commands**:
```cpp
// In loop() switch statement:
case 'X':           // Your custom command
  customFunction();
  break;

// Define function:

  // Your code here
  Serial.println("Custom action executed");
}
```

### Performance Optimization

1. **Reduce Serial Output** for faster command processing
2. **Use PWM Frequency** matching motor characteristics (typically 20kHz on ESP32)
3. **Filter Noisy Sensors** with capacitors on motor power lines
4. **Implement Acceleration Curves** for smoother movement
